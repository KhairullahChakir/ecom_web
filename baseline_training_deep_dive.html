Deep Dive: Baseline Training Performance

Deep Dive: 01_baseline_training.ipynb

This notebook establishes the performance "floor" for the purchase intention prediction task using classical machine learning algorithms. It serves as a benchmark for the more complex deep learning models (DeepFM, TabM, etc.) trained in later notebooks.

1. Data Demographics & Target

The dataset contains 12,330 sessions from an e-commerce site. * Target Variable (Revenue): A Boolean indicating if a purchase was made. * Class Imbalance: Approximately 84.5% of sessions do NOT result in a purchase (False), while only 15.5% result in a purchase (True). This imbalance is a critical challenge addressed in the "Balancing" section.

2. Feature Engineering & Preprocessing

A. Feature Categorization

The notebook splits features into two types: * Categorical: Month, VisitorType, Weekend. * Numerical: Includes Behavioral metrics (Administrative, ExitRates) and Google Analytics derived metrics (PageValues, BounceRates).

B. Encoding & Scaling

  • Label Encoding: Categorical strings are converted to integers using LabelEncoder. For example, Month is mapped (e.g., Feb -> 2, Mar -> 5).
  • Standard Scaling: Numerical features are normalized using StandardScaler to have a Mean of 0 and Standard Deviation of 1. This is mandatory for models like Logistic Regression and SVM which are sensitive to the magnitude of feature values.

C. Data Split Strategy

The notebook uses a robust 80/10/10 split: 1. Training (80%): Used to teach the models. 2. Testing (10%): Used for the final benchmark metrics in the notebook. 3. Validation (10%): Reserved for hyperparameter tuning or early stopping in DL models. * Stratification: stratify=y is used to ensure that the 15.5% purchase rate is maintained exactly across all three sets.

D. Balancing the Training Set

Because the model could achieve 84% accuracy by simply guessing "No Purchase," the notebook balances the training set using Oversampling: * The minority class (Revenue=1) is duplicated (resample with replace=True) until it matches the count of the majority class. * The final training set size is 16,676 rows, providing balanced signal for both outcomes.

3. Model Zoo & Benchmarking

Broad categories of algorithms are tested: * Linear: Logistic Regression. * Tree-Based (Non-Linear): Decision Tree, Random Forest, and XGBoost. * Kernel-Based: SVM (Support Vector Machine).

Key Metric Comparison (Example Results)

Model AUC-ROC F1-Score Recall (Capturing Buyers)
XGBoost ~0.92 ~0.68 High (~75%)
Random Forest ~0.93 ~0.66 Moderate (~66%)
Logistic Reg. ~0.90 ~0.65 High (~76%)

Insight: XGBoost and Random Forest typically lead in AUC-ROC. Tree-based models handle the non-linear relationship between "Page Duration" and "Revenue" better than linear models.

4. Diagnostics & Visualizations

A. Feature Importance

The notebook plots importance for XGBoost and Random Forest. * PageValues almost always emerges as the #1 predictor. It represents the average value for a web page that a user visited before completing an e-commerce transaction.

B. ROC Curves

The Area Under the Curve (AUC) measures the model's ability to distinguish between buyers and non-buyers at all classification thresholds. A curve hugging the top-left corner indicates a superior model.

C. Confusion Matrix

Analyzes where the system fails: * False Positives: Predicting a purchase when there wasn't one (potential waste of marketing budget). * False Negatives: Missing a customer who was going to buy (lost revenue insight).

5. Artifact Output

The notebook saves the trained models as .joblib files in ../backend/models/. These are the "Baseline" brains used by the API if the complex deep learning models are not available.
