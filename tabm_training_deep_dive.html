Deep Dive: Advanced Deep Learning Model Training (TabM)

Analysis of 02_tabm_training.ipynb

1. Overview

This notebook shifts from classical ML to advanced deep learning architectures designed specifically for tabular data. It implements a "Tournament" style benchmark between three state-of-the-art models to predict purchase intent.

2. The Data Deep Learning Pipeline

Unlike classical models (XGBoost/RF) that treat all numbers as equal, the deep learning pipeline uses Categorical Embeddings: - Preprocessing: Categorical features undergo LabelEncoding followed by an nn.Embedding layer in the models. - Numerical Scaling: Standard StandardScaler is used to ensure numerical inputs have zero mean and unit variance, critical for neural network convergence. - Class Imbalance Handling: Instead of oversampling (used in the baseline), this notebook implements Weighted Loss (pos_weight ≈ 5.46) within the BCEWithLogitsLoss function. This penalizes the model more for missing a "Purchaser" (class 1).

3. Architecture Breakdown

A. DeepFM (Deep Factorization Machines)

  • Concept: Combines the power of Factorization Machines (capturing low-order feature interactions) with Deep Neural Networks (capturing high-order non-linearities).
  • Core Unit: fm_out = 0.5 * torch.sum(sum_square - square_sum, dim=1) handles the interaction terms.

B. TabM (Ensemble MLP) - Top Performer

  • Concept: An "Ensemble" model where multiple MLP heads are trained simultaneously, and their predictions are averaged.
  • Key Feature: High robustness to tabular noise. Uses GELU activation and BatchNorm extensively.
  • Performance: Achieved the highest Val AUC (~0.92) in the benchmark.

C. FT-Transformer (Feature Tokenizer + Transformer)

  • Concept: Adapts the standard Transformer (used in GPT/BERT) for tabular data.
  • Architecture:
    1. Tokenizer: Converts each feature (categorical and numerical) into a vector (token).
    2. CLS Token: A special token used to aggregate information across all features via self-attention.
    3. Transformer Encoder: 3 layers deep with 4 attention heads.

4. Training Logistics

  • Optimizer: AdamW (Adam with decoupled Weight Decay) for better regularization.
  • Scheduler: CosineAnnealingLR for smooth learning rate decay across 30 epochs.
  • Device: Auto-detects CUDA (GPU) for hardware acceleration.
  • Persistence: Automatically reloads the "Best Weights" from .pt files after training to ensure evaluation is done on the peak model state.
