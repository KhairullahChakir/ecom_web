Analysis of 04_model_pruning.ipynb

1. Objective

Following the discovery that TabM is the strongest model, this phase explores the Pruning Efficiency Frontier. The goal is to determine if we can reduce the ensemble size (K) to save memory and further reduce latency without sacrificing significant predictive power.

2. Pruning Strategy: Ensemble Reduction

Unlike weight pruning (removing individual neurons), this notebook focuses on Ensemble Pruning. - TabM K=4: The full ensemble (4 parallel MLP blocks). - TabM K=2: A medium ensemble (2 parallel MLP blocks). - TabM K=1: A single MLP (Essentially fallback to a standard MLP with TabM embeddings).

Why Ensemble Pruning?

Since TabM's primary innovation is the efficient batch-parallel ensemble, reducing K directly reduces the number of matrix multiplications required for a single inference pass.

The notebook contains an "Efficiency Frontier" plot that visualizes this trade-off. - The Sweet Spot: K=4 remains the winner for raw accuracy. - The Production Choice: While K=4 is fast (0.17ms), the e-commerce backend actually uses an even more pruned/optimized version for maximum throughput, as demonstrated in the final backend/models/ artifacts.

5. Technical Implementation Details

  • Training: Each variant was trained for 20 epochs using AdamW and CosineAnnealingLR.
  • Export: Models were exported to ONNX using dynamic axes, allowing the backend to handle varying batch sizes.
  • Benchmarking: Latency was measured using time.perf_counter with 100 warmup runs and 1000 benchmark loops on the CPU provider.

6. Conclusion

Model pruning proves that the TabM architecture is extremely robust. Even when reduced to a single MLP (K=1), the sophisticated feature embeddings and preprocessing allow it to outperform standard baselines while maintaining sub-millisecond sub-latency.
