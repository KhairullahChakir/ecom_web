Analysis of 03_latency_benchmarking.ipynb

1. Objective

This notebook serves as the "Grand Leaderboard." Its purpose is to reconcile model accuracy (from previous phases) with inference speed, identifying which model is actually viable for high-traffic production use (the "AI Brain").

2. Comparison Categories

A. Classical ML (Scikit-learn)

  • Models: Logistic Regression, Random Forest, XGBoost.
  • Latency: These models are generally fast because they are implemented in C++ with minimal overhead.
  • Observation: Random Forest was the outlier, being significantly slower (~91ms) due to the depth of the ensemble.

B. Deep Learning (PyTorch Raw)

  • Models: DeepFM, TabM (K=4), FT-Transformer.
  • Latency: PyTorch models in their raw state carry significant Python overhead for single-sample inference.
  • Range: ~5ms to ~17ms.

C. Optimized Neural (TorchScript & ONNX)

  • TorchScript: Tracing the model for the JIT compiler. In this specific benchmark, it showed higher latency (~107ms), likely due to the tracing overhead on a relatively small model for a single sample.
  • ONNX (Open Neural Network Exchange): The absolute winner. By exporting to ONNX and using onnxruntime with the CPU provider, latency dropped to 0.11ms.

3. The Power of ONNX Optimization

The jump from raw PyTorch TabM (16.6ms) to ONNX TabM (0.11ms) represents a ~150x speed increase. - Static Graph: ONNX converts the dynamic PyTorch graph into a fixed execution plan. - Operator Fusion: Multiple neural network operations are combined into single, highly optimized kernels. - C++ Backend: Eliminates the Python Global Interpreter Lock (GIL) overhead during prediction.

It provides the state-of-the-art accuracy of the TabM ensemble while maintaining sub-millisecond response times, ensuring that the user experience on the e-commerce demo is never bogged down by AI inference.
